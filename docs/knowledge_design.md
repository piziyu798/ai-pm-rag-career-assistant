# 知识库框架设计

## 1. 总体结构

本知识库由 6 个子库组成：

1. JD 库
2. AI 产品知识库
3. 能力模型库
4. 项目案例库
5. 简历模板库
6. 面试题库

它们共同服务 5 个 MVP 场景：

| 场景 | 主知识库 | 辅助知识库 |
|---|---|---|
| JD 解析 | JD 库、能力模型库 | AI 产品知识库 |
| 能力诊断 | 能力模型库、JD 库 | 项目案例库 |
| 项目包装 | 项目案例库、简历模板库 | 能力模型库 |
| 面试准备 | 面试题库、AI 产品知识库 | 项目案例库、JD 库 |
| 知识问答 | AI 产品知识库 | 面试题库、项目案例库 |

## 2. 设计原则

### 原则一：内容要可引用

每条知识都要尽量保留：
- 标题
- 来源名称
- 来源链接
- 可信度
- 原始内容

### 原则二：内容要能服务任务

不要只存百科解释。每条内容最好能回答：
- 它适合哪个场景？
- 它能帮用户完成什么任务？
- 它和求职有什么关系？

### 原则三：标签比数量更重要

第一版知识库不要盲目堆内容。宁愿 100 条高质量、标签准确的 chunk，也不要 1000 条没有结构的文本。

### 原则四：AI 产品经理语境优先

同样是 RAG 概念，知识库中应该保留三种表达：
- 概念定义
- 产品经理视角
- 面试表达方式
