# AI 产品经理求职 RAG 助手：产品需求文档 PRD

> 版本：v1.0  
> 日期：2026-05-07  
> 产品阶段：MVP Demo

---

## 1. 项目背景

随着大模型、RAG、Agent、AIGC 等技术快速进入产品岗位要求，AI 产品经理实习岗位对候选人的能力要求发生变化。候选人不仅需要具备传统产品经理能力，如需求分析、PRD、原型、项目推进，也需要理解 RAG、Agent、Prompt Engineering、AI 产品评估、模型能力边界等 AI 相关知识。

然而，对于多数学生和转型求职者来说，当前存在以下问题：

1. 岗位 JD 分散，难以判断 AI 产品经理真正需要哪些能力；
2. AI 技术知识碎片化，学习资料多但缺少产品经理视角；
3. 不知道自己的背景与目标岗位之间差距在哪里；
4. 做过 AI 项目，但不知道如何包装成产品经理项目经历；
5. 面试中容易背概念，无法结合项目和岗位要求表达。

因此，本项目希望构建一个面向 AI 产品经理求职场景的 RAG 助手，帮助用户完成 JD 理解、AI 技术学习、能力诊断、项目包装和面试准备。

---

## 2. 目标用户

| 用户类型 | 典型特征 | 核心需求 |
|---|---|---|
| AI 产品经理实习求职者 | 在校生，缺少正式产品实习经验 | 理解岗位要求，准备项目和面试 |
| 传统产品经理转 AI 产品方向 | 有产品基础，但 AI 技术理解不足 | 快速补齐 RAG、Agent、Prompt 等知识 |
| 技术/数据背景学生转产品 | 会 Python/SQL 或做过项目，但缺少产品表达 | 将技术项目包装成产品经历 |
| AI 工具/Agent 项目实践者 | 用 Dify/Coze/Cursor 等工具做过 Demo | 将工具实践升级为产品能力表达 |

---

## 3. 用户痛点

| 痛点 | 说明 | 产品机会 |
|---|---|---|
| 看不懂 AI PM JD | JD 中充满 RAG、Agent、Prompt、Workflow 等术语 | 提供 JD 解析和能力关键词提取 |
| 技术学习缺少产品视角 | 很多资料偏工程实现，不适合产品经理 | 用产品经理能理解的方式解释 AI 技术 |
| 不知道自己差在哪里 | 用户难以判断自己是否达到实习要求 | 基于能力模型输出差距诊断 |
| 项目不会包装 | 技术项目容易写成工具堆砌 | 转化为目标用户、痛点、方案、指标、AI 机制 |
| 面试表达不成体系 | 容易背概念，不能结合项目和岗位 | 生成回答框架、示例回答和追问预测 |

---

## 4. MVP 功能范围

本项目 MVP 保留 5 个核心场景：

| 功能 | 场景名 | 说明 |
|---|---|---|
| AI 技术知识问答 | 知识问答 | 回答 RAG、Agent、Prompt、Function Calling 等技术概念 |
| AI 产品经理 JD 解析 | JD解析 | 总结岗位方向、技术能力、产品能力和准备建议 |
| 个人能力诊断 | 能力诊断 | 根据用户背景判断 L1-L5 能力水平和差距 |
| AI 项目包装 | 项目包装 | 将用户项目转化为简历 bullet 和面试表达 |
| AI 产品面试准备 | 面试准备 | 生成面试回答框架、示例回答和追问预测 |

MVP 暂不包含：

1. 用户账号系统；
2. 简历文件自动解析；
3. 自动投递；
4. 多轮长期记忆；
5. 课程学习路径推荐；
6. AI 作业批改；
7. 实战任务训练。

---

## 5. 核心用户流程

```text
用户进入页面
  ↓
选择使用场景
  ↓
输入问题 / 背景 / 项目 / JD
  ↓
系统检索相关知识库
  ↓
LLM 基于上下文生成结构化回答
  ↓
展示回答和参考来源
  ↓
用户根据结果准备简历、项目或面试
```

7. 回答展示区；

## 7. 系统架构

```text
Streamlit 前端
  ↓ HTTP 请求
FastAPI 后端
  ↓
rag_answer.py 核心逻辑
  ↓
BGE Embedding
  ↓
Qdrant 向量数据库
  ↓
检索 JD / AI知识 / 能力模型 chunks
  ↓
Prompt 拼接
  ↓
硅基流动 / OpenAI Compatible LLM
  ↓
结构化回答 + 来源返回
```

## 8. 成功指标

| 指标 | MVP 验收标准 |
|---|---|
| 场景覆盖 | 覆盖 5 个核心求职场景 |
| 知识库规模 | 至少包含 JD、AI 技术知识、能力模型三类知识 |
| 检索质量 | 15 条测试样例中大多数能召回相关内容 |
| 回答质量 | 综合评分 >= 4.0 视为通过 |
| 可演示性 | 能通过浏览器完成完整交互 |
| 可溯源性 | 回答后展示参考来源 |
